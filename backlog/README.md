# Backlog

- `backlog.csv` is the source of truth for the initial backlog (generated by `make_backlog.py`; edit either).
- `milestones.json` defines M0 to M5.
- `setup_github.py` creates labels, milestones, issues and a Project board.

```bash
gh auth login && gh auth refresh -s project
pip install pyyaml
python backlog/setup_github.py YOUR_ORG/decoder-watermark-hardening --dry-run   # preview
python backlog/setup_github.py YOUR_ORG/decoder-watermark-hardening
```

## Milestones
| ID | Name | Exit criterion |
|---|---|---|
| N | Novelty gate (parallel) | Checks 1-7 logged; go/pivot ADR signed off by guide; re-run monthly |
| M0 | Repo setup and Review-2 import | CI green, protection on, GPU env pinned |
| M1 | Phase 1 Embedding | Re-implemented embedding reproduces baseline bit accuracy and quality |
| M2 | Phase 2 Detection and FPR audit | Detector wired, threshold from calibration, >=10k-negative audit with CIs, protocol frozen |
| M3 | Phase 3 Attacks | Image and weight attack suites; D0 cost curves (RQ1) |
| M4 | Phase 4 Defenses | D0-D3, 3 seeds, matched compute, 2x2 analysis (RQ2) |
| M5 | Mode B, extensions, write-up | Reproducible release, paper draft, demo |

Tiers (`tier:1/2/3` labels) follow the proposal: cut from the bottom if time runs short.

## Board columns
Backlog -> Ready (has acceptance criteria + owner) -> In progress -> In review -> Done.
Rules: max 2 items In progress per person; P0 items first; `claims-risk` PRs need a second reviewer.
